# MCP Apps

[MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview){.external-link target="_blank"} — the `io.modelcontextprotocol/ui` extension — lets a server hand a host a **real interface** instead of a wall of text. `ag2.mcp` serves one as an **app**: a document plus the tools that render it, served next to your agent by `MCPServer`.

## Quick start

```bash
pip install "ag2[mcp,anthropic]" uvicorn
```

### Write

An agent with a UI: the host's model calls `show_recipe`, the tool asks the agent for a typed `Recipe`, and the host renders it as a card.

```python linenums="1" hl_lines="38 40 42 45-46 51"
import asyncio
import sys

import uvicorn
from pydantic import BaseModel

from ag2 import Agent
from ag2.config import AnthropicConfig
from ag2.mcp import MCPApp, MCPServer

class Recipe(BaseModel):
    title: str
    minutes: int
    ingredients: list[str]

    def __str__(self) -> str:
        return f"{self.title} ({self.minutes} min): {', '.join(self.ingredients)}"

CARD = """<h2 id="title">Cooking…</h2>
<ul id="ingredients"></ul>
<script>
  ag2ui.onToolResult(function (result) {
    var recipe = result.structuredContent;
    document.getElementById("title").textContent = recipe.title + " · " + recipe.minutes + " min";
    document.getElementById("ingredients").innerHTML = "";
    recipe.ingredients.forEach(function (name) {
      var li = document.createElement("li");
      li.textContent = name;
      document.getElementById("ingredients").appendChild(li);
    });
  });
</script>"""

chef = Agent(
    "chef",
    prompt="You write short home-cooking recipes.",
    config=AnthropicConfig(model="claude-sonnet-5"),
    response_schema=Recipe,
)
cookbook = MCPApp("ui://cookbook/recipe", CARD)

@cookbook.tool
async def show_recipe(dish: str) -> Recipe:
    """Show a recipe for a dish as a card."""
    reply = await chef.ask(f"A recipe for {dish}.")
    recipe = await reply.content()
    if recipe is None:
        raise RuntimeError("The chef returned no recipe.")
    return recipe

app = MCPServer(chef, apps=[cookbook])

if __name__ == "__main__":
    if "--stdio" in sys.argv:
        asyncio.run(app.run_stdio())
    else:
        uvicorn.run(app, host="127.0.0.1", port=3001)
```

`ag2ui` in the HTML is not a package you install: `MCPServer` injects it into the document before serving it, and it performs the handshake a host requires before it shows anything — see [Inside the document](#inside-the-document-ag2ui). The tool's return type is the card's data: its fields arrive in the document as `structuredContent`, and its `__str__` is what the model reads — see [The return type does three jobs](#the-return-type-does-three-jobs).

### Run

```bash
python recipes.py
```

The server listens on **`http://127.0.0.1:3001/mcp`**. `python recipes.py --stdio` serves over stdin/stdout instead, for hosts that launch the server themselves.

### Who calls what

!!! note "Three callers, one server"
    - **The host's model** calls `show_recipe` — the tool bound to the document. It never calls your HTML.
    - **The document** calls tools through the host with `ag2ui.callTool(...)`. A tool meant only for it is declared with `visibility=["app"]` — see [Who may call a tool](#who-may-call-a-tool).
    - **The AG2 agent** is what *your tool* calls with `chef.ask(...)`. To the host it is one more tool, `ask`, which `MCPServer` always lists; the model may call it directly too, and gets text back.

    And the document itself: the host fetches it **in parallel with** the call, so it is a static body, and each call's data reaches it afterwards as the result's `structuredContent`.

An app whose tools do not need a model — a counter, a form, a view over your own data — is the same code with a plain function body. `MCPServer` still takes an agent, and the host's model still sees its `ask` tool next to yours: give that agent a prompt that says what it is for.

### Test without a host

`ag2.mcp.testing.connect` opens an in-process client against the server — here `app` from the quick start. Advertise MCP Apps support the way a host does, and you see exactly what a host would — the binding, the result, the document:

```python linenums="1" hl_lines="7"
import asyncio

from ag2.mcp.apps import APP_MIME_TYPE, EXTENSION_ID
from ag2.mcp.testing import connect

async def main() -> None:
    async with connect(app, extensions={EXTENSION_ID: {"mimeTypes": [APP_MIME_TYPE]}}) as session:
        tools = await session.list_tools()
        result = await session.call_tool("show_recipe", {"dish": "shakshuka"})
        card = await session.read_resource("ui://cookbook/recipe")

    print([tool.meta for tool in tools.tools])   # show_recipe carries {"ui": {"resourceUri": ...}}
    print(result.structured_content)             # the card's data
    print(card.contents[0].mime_type)            # text/html;profile=mcp-app

asyncio.run(main())
```

Leave `extensions=` out to see what a text-only client gets. An app tool also stays callable as the function you wrote, so a unit test can skip MCP altogether — `#!python await show_recipe("shakshuka")` — and give the agent a `ag2.testing.TestConfig` to script its reply.

## MCP Apps or MCP-UI?

Use MCP Apps for new work. [MCP-UI](https://mcpui.dev/){.external-link target="_blank"}'s own SDK now implements MCP Apps, and the embedded-resource pattern that [`ag2.mcp_ui`](/docs/user-guide/tools/mcp_ui) serves — a handler that builds HTML from its arguments and returns it inside the result — is the one a host implementing MCP Apps will not render. `ag2.mcp_ui` remains for clients that only understand MCP-UI resources.

## The return type does three jobs

`Recipe` above is doing more work than it looks. From one annotation the framework derives all three of the things MCP wants:

| From `-> Recipe` | Becomes | Read by |
|---|---|---|
| its JSON schema | the tool's `outputSchema` | the client, to validate |
| its dump | the result's `structuredContent` | your document |
| its `__str__` | the result's text content | the model, and a text-only client |

Which is why `__str__` is worth writing: a text-only client gets *"Shakshuka (25 min): eggs, tomatoes, …"* rather than a JSON dump.

Both pydantic models and dataclasses work. This applies to any custom tool, not only a UI-bound one — see [Beyond the conversational tool](/docs/user-guide/tools/serving_mcp#beyond-the-conversational-tool).

For Pydantic models, `outputSchema` describes `model_dump(mode="json")`, including serialized field types and each nested model's `serialize_by_alias` policy. Input-only aliases do not become output keys. An explicit `output_schema=` still takes precedence, and a manually returned `CallToolResult` keeps the content you supplied.

### Three levels of control

A handler returns whichever of these fits, in increasing order of control:

```python linenums="1"
from dataclasses import dataclass

from mcp.types import CallToolResult, TextContent

from ag2.mcp import MCPApp

@dataclass
class Item:
    name: str
    price: int

    def __str__(self) -> str:
        return f"{self.name} costs ${self.price}."

shop = MCPApp("ui://shop/card", "<div id='card'></div>")

@shop.tool
async def typed() -> Item:
    """A typed value: schema, structured content and text all derived."""
    return Item(name="Espresso cup", price=12)

@shop.tool
async def mapping() -> dict:
    """A mapping: structured content verbatim, text a JSON rendering, no schema."""
    return {"name": "Espresso cup", "price": 12}

@shop.tool
async def explicit() -> CallToolResult:
    """A full result: nothing derived. Also how you state text and data separately."""
    return CallToolResult(
        content=[TextContent(type="text", text="One espresso cup, $12.")],
        structuredContent={"name": "Espresso cup", "price": 12},
    )
```

The snippets below reuse this `shop` app and `Item`.

!!! note "The schema follows the annotation, not the value"
    `outputSchema` is decided once, when the tool is declared. Annotating `-> CallToolResult` is what opts a tool out of an advertised schema; returning one from a handler annotated `-> Item` still advertises `Item`'s schema, and MCP requires your `structuredContent` to conform to it. For a Pydantic model this is its serialization schema. If you assemble a different shape by hand, supply an explicit `output_schema=` or annotate the handler `-> CallToolResult`.

## Inside the document: `ag2ui`

A host **discards every message from a view that has not completed the `ui/initialize` handshake**, and tells it nothing. A hand-written button on a document without that handshake is silently dead — which is why the runtime is injected by default. The server places a `<script>` at the head of the document before serving it — inside `<head>` when there is one, after `<html>` when there is not, at the very front of a fragment — so by the time your own script runs the global exists.

It defines one global, `ag2ui`:

```javascript
await ag2ui.ready;                       // the handshake completed

ag2ui.onToolResult(fn);                  // every result for this document
ag2ui.onToolResult("show_item", fn);     // only that tool's results
ag2ui.onToolInput(fn);                   // the call's arguments
ag2ui.onToolInputPartial(fn);            // arguments while the model is still writing them
ag2ui.onHostContextChanged(fn);          // theme, display mode, styles, locale…
ag2ui.onCancelled(fn);

await ag2ui.callTool("add_to_cart", { item_id: "42" });
await ag2ui.sendMessage("Show me the kettle");   // into the conversation
await ag2ui.openLink("https://example.com");
await ag2ui.readResource("ui://shop/card");
await ag2ui.updateContext({ content: [{ type: "text", text: "Viewing item 42" }] });
await ag2ui.requestDisplayMode("fullscreen");
await ag2ui.downloadFile(contents);
await ag2ui.sampling({ messages: [...] });
ag2ui.log("info", "rendered");
ag2ui.reportSize();                      // force a size report; it is automatic otherwise

ag2ui.host.capabilities;     // what the host advertised
ag2ui.host.context;          // theme, styles, display mode, container size
ag2ui.host.protocolVersion;  // the dialect revision the host answered with
ag2ui.host.info;             // the host's name and version
```

The runtime introduces the document to the host in `ui/initialize` as `appInfo`: its `name` is the app's `name`, else the URI without `ui://` (`shop/card`), and its `title`, the label a host shows people, is the app's `title` when it has one.

Each subscription returns an unsubscribe function. The document's size is reported automatically via a `ResizeObserver`, so the host can size the frame without your writing one.

**Subscribe whenever you like; call only after `ag2ui.ready`.** Registering a handler is local and is safe the moment the document parses — which is why the card above awaits nothing. Everything that *talks* to the host is refused until the handshake completes, so `await ag2ui.ready` before the first `callTool`, `sendMessage` or `readResource`; calling earlier throws rather than posting into a channel the host is still discarding.

**Use what `callTool` returns.** `#!javascript await ag2ui.callTool(...)` resolves with the call's result, so a button renders it directly. Whether the host *also* pushes that result to `onToolResult` subscribers varies by host, so do not wait for it.

Errors arrive on the **same** channel as results — a failed call is a result carrying `isError`, matching how `ag2.mcp` already treats a tool error as a result rather than an exception.

Calling something the host did not advertise **throws in JavaScript before anything is sent**, because a host's own answer to an unadvertised method is silence:

```javascript
try {
  await ag2ui.downloadFile(contents);
} catch (e) {
  // "the host did not advertise 'downloadFile'" — rather than a button that does nothing.
}
```

`requestDisplayMode` refuses locally in the same way, against `ag2ui.host.context.availableDisplayModes` rather than against a capability: asking for a mode the host never offered throws instead of hanging on an answer that will not come.

### Which tool answered

MCP Apps gives the document nothing to correlate with: the notification carrying a result names neither the call nor the tool. With one tool per document that does not matter. With two — a card that renders itself *and* updates after an action — it does.

The server therefore stamps the answering tool's name into the result's `_meta` under `ai.ag2/tool`, and `ag2ui.onToolResult(name, fn)` routes on it:

```javascript
ag2ui.onToolResult("show_item", renderCard);
ag2ui.onToolResult("add_to_cart", showConfirmation);
```

Set that key yourself and your value travels instead, so you can route by your own scheme. This is the one respect in which a `CallToolResult` you assembled yourself is modified; every other key you set travels untouched alongside the stamp.

### Who may call a tool

A tool the document calls through `ag2ui.callTool` need not be one the model can call. `visibility=` says where the host surfaces it — `"model"` in the model's tool list, `"app"` to the document:

```python linenums="1" hl_lines="13"
@dataclass
class CartLine:
    status: str

    def __str__(self) -> str:
        return self.status

@shop.tool
async def show_item(item_id: str) -> Item:
    """Show a product card."""
    return Item(name="Espresso cup", price=12)

@shop.tool(visibility=["app"])
async def add_to_cart(item_id: str) -> CartLine:
    """Add an item to the cart. Called by the card's button, not by the model."""
    return CartLine(status="Added to your cart")
```

Omit it and no `visibility` is advertised at all, leaving the host to its own default. It is a hint about where to *surface* a tool, not an authorization boundary: the tool is served and dispatched exactly like any other, so anything that must not be called by the model has to refuse in the handler.

`examples/mcp/server_apps.py` is a runnable version of this shop, with a button that calls `add_to_cart`.

## Using the upstream `App` SDK instead

`ag2ui` is one way to talk to the host, not the only one. A document written against the `App` class from [`@modelcontextprotocol/ext-apps`](https://github.com/modelcontextprotocol/ext-apps){.external-link target="_blank"} works as it is: **a body with a `<script>` that loads `@modelcontextprotocol/ext-apps` — a `src` or an `import` naming the package — or whose code carries the `"ui/initialize"` method name as a string (a bundle that inlined the SDK) is served without `ag2ui`**, so the host does not see two handshakes. Only `<script>` elements the browser runs are searched: text the page displays, quoted or not, does not count, and neither does a script that is commented out, sits inside `<template>` or `<noscript>`, or has a data `type` such as `application/json`. A document that loads the SDK some other way — from a file whose URL does not name the package — is not recognised; pass `inject_runtime=False` for it. A recognised document that also calls `ag2ui.` logs a warning on `ag2.mcp.apps`, since `ag2ui` will not exist there.

The two cover the same ground:

| `ag2ui` | `App` from `@modelcontextprotocol/ext-apps` |
|---|---|
| injected; `await ag2ui.ready` | `const app = new App({ name, version })`; `await app.connect()` |
| `ag2ui.onToolResult(fn)` | `app.ontoolresult = fn` |
| `ag2ui.onToolResult("show_item", fn)` | `app.ontoolresult = fn`, routing on `result._meta["ai.ag2/tool"]` yourself |
| `ag2ui.onToolInput(fn)` | `app.ontoolinput = fn` |
| `ag2ui.onToolInputPartial(fn)` | `app.ontoolinputpartial = fn` |
| `ag2ui.onHostContextChanged(fn)` | `app.onhostcontextchanged = fn` |
| `ag2ui.onCancelled(fn)` | `app.ontoolcancelled = fn` |
| `ag2ui.callTool("add_to_cart", { item_id: "42" })` | `app.callServerTool({ name: "add_to_cart", arguments: { item_id: "42" } })` |
| `ag2ui.sendMessage("Show me the kettle")` | `app.sendMessage({ role: "user", content: [{ type: "text", text: "Show me the kettle" }] })` |
| `ag2ui.openLink(url)` | `app.openLink({ url })` |
| `ag2ui.readResource(uri)` | `app.readServerResource({ uri })` |
| `ag2ui.updateContext({ content })` | `app.updateModelContext({ content })` |
| `ag2ui.requestDisplayMode("fullscreen")` | `app.requestDisplayMode({ mode: "fullscreen" })` |
| `ag2ui.downloadFile(contents)` | `app.downloadFile({ contents })` |
| `ag2ui.sampling({ messages, maxTokens })` | `app.createSamplingMessage({ messages, maxTokens })` |
| `ag2ui.log("info", "rendered")` | `app.sendLog({ level: "info", data: "rendered" })` |
| `ag2ui.host.capabilities` / `ag2ui.host.context` | `app.getHostCapabilities()` / `app.getHostContext()` |

One difference in shape: each `ag2ui.on…` call adds a subscriber and returns an unsubscribe function, while each `app.on…` property holds a single handler.

Choose `ag2ui` for a small hand-written document with no build step and no network access; choose `App` when you already use it, want its React bindings and theming helpers, or share the document with servers written in other languages.

Without a bundler, load the SDK's self-contained `app-with-deps` build from a CDN. The example below is the shop card from [above](#who-may-call-a-tool), whole: the document lives in its own `card.html` and talks to the host through `App`, and the server passes its path to `MCPApp` and declares the tools on the same `shop`. The host's default sandbox blocks every external script, so **declare the CDN in `csp=`** or the import fails silently:

```html linenums="1" title="card.html" hl_lines="11"
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>Product card</title>
</head>
<body>
  <div id="card">Loading…</div>
  <button id="add">Add to cart</button>
  <script type="module">
    import { App } from "https://unpkg.com/@modelcontextprotocol/ext-apps@2/app-with-deps";

    const app = new App({ name: "shop/card", title: "Product card", version: "1.0.0" });
    app.ontoolresult = (result) => {
      document.getElementById("card").textContent = `${result.structuredContent.name}: $${result.structuredContent.price}`;
    };
    await app.connect();

    document.getElementById("add").onclick = async () => {
      const result = await app.callServerTool({ name: "add_to_cart", arguments: { item_id: "42" } });
      document.getElementById("card").textContent = result.content[0].text;
    };
  </script>
</body>
</html>
```

```python linenums="1" title="server.py" hl_lines="23-28"
from dataclasses import dataclass
from pathlib import Path

from ag2 import Agent
from ag2.config import AnthropicConfig
from ag2.mcp import MCPApp, MCPServer, ResourceCsp

@dataclass
class Item:
    name: str
    price: int

    def __str__(self) -> str:
        return f"{self.name} costs ${self.price}."

@dataclass
class CartLine:
    status: str

    def __str__(self) -> str:
        return self.status

shop = MCPApp(
    "ui://shop/card",
    Path(__file__).parent / "card.html",
    title="Product card",
    csp=ResourceCsp(resource_domains=["https://unpkg.com"]),
)

@shop.tool
async def show_item(item_id: str) -> Item:
    """Show a product card."""
    return Item(name="Espresso cup", price=12)

@shop.tool(visibility=["app"])
async def add_to_cart(item_id: str) -> CartLine:
    """Add an item to the cart. Called by the card's button, not by the model."""
    return CartLine(status="Added to your cart")

agent = Agent("shop", prompt="You help customers browse the shop.", config=AnthropicConfig(model="claude-sonnet-5"))
server = MCPServer(agent, apps=[shop])
```

The file is read on every resource read, so editing `card.html` needs no server restart. Serve `server` exactly as in the [quick start](#run). Register handlers before `app.connect()`, as the SDK's own docs ask: the host may deliver the tool result as soon as the handshake completes.

## Bringing your own bundle

A bundle that inlined the upstream SDK is usually recognised by its handshake and served untouched, as above. A hand-written runtime that sends `"ui/initialize"` is recognised the same way. For one that builds the method name at run time, or loads the SDK from a URL that does not name the package, pass `inject_runtime=False`: injection is off and the body is served byte-for-byte as you wrote it. `app.runtime_script()` returns the same `<script>` element as text if you would rather place it yourself — a body that already carries it is not given a second copy.

```python linenums="1"
from pathlib import Path

from ag2.mcp import MCPApp

shop = MCPApp("ui://shop/card", Path("dist/card.html"), inject_runtime=False)
```

## When the host shows text only

**The UI binding is withheld from a client that did not advertise the extension.** It is a promise that the client can read the document and render it; to a client that cannot, it is a promise about a document it will never fetch. There is no switch — this is correctness, not policy.

The server says so. The first `tools/list` from such a client logs a warning on `ag2.mcp.server` naming the tools whose binding was withheld — once per connection. A `stateless=True` HTTP server and a 2026-07-28 client make every request its own connection, so there it repeats per `tools/list`. If your host shows only text, that line tells you whether it advertised `io.modelcontextprotocol/ui` at all.

That client sees the same tool without `_meta.ui`, calls it successfully, and gets the text your `__str__` produced. Because a UI-bound tool always returns text alongside its data, you usually need no branch at all. When you want to word an answer differently:

```python linenums="1"
from ag2.mcp import MCPRequestContext, client_supports_apps

@shop.tool
async def describe_item(item_id: str, ctx: MCPRequestContext) -> Item:
    """Show a product card."""
    item = Item(name="Espresso cup", price=12)
    if not client_supports_apps(ctx):
        ...  # a fuller sentence, since there will be no card
    return item
```

A client that advertised the identifier but not the `text/html;profile=mcp-app` MIME type counts as unable to render — advertising the extension alone says nothing about being able to display the one format a document arrives in.

A server holding at least one app also advertises the extension itself, with empty settings. Be clear-eyed about what that is worth: the specification defines only the client direction and says nothing about servers advertising at all, and a handshake-era client never receives a server's `extensions` — that field exists only in the 2026-07-28 wire schema. It is visible in discovery and inert otherwise.

## Common mistakes

Each of these produces an error or a warning that says what to do:

- **Giving an app tool to an agent.** `Agent(tools=[show_recipe])` raises a `TypeError`: an `@app.tool` / `@mcp_tool` tool is served to MCP clients through `MCPServer(apps=...)` / `MCPServer(tools=...)`. To give the same function to an agent, decorate it with `@tool` instead.
- **A file name as a string.** A `str` body is always literal HTML, so `MCPApp("ui://shop/card", "card.html")` serves the text `card.html`. A string with no markup that ends in `.html` / `.htm` logs a warning on `ag2.mcp.apps` suggesting `Path("card.html")`.
- **Declaring a tool after the server is built** raises `ag2.mcp.errors.MCPAppFrozenError` naming the tool — see [Taking an app apart](#taking-an-app-apart).
- **Using `ag2ui` in a document built on the upstream `App`.** Such a document is served without `ag2ui`, so the call fails in the browser; the server logs a warning on `ag2.mcp.apps` naming the document. Use one or the other — see [Using the upstream `App` SDK instead](#using-the-upstream-app-sdk-instead).
- **A host that never renders** — see [When the host shows text only](#when-the-host-shows-text-only).

## Reference

### Where the body comes from

`content` takes four forms, told apart **by type alone** — never by looking at the filesystem, so a string is always literal HTML and never a filename:

```python linenums="1"
from pathlib import Path

from ag2 import Variable
from ag2.mcp import MCPApp

def render_card() -> str:
    return "<div id='card'></div>"

MCPApp("ui://shop/card", "<div id='card'></div>")       # inline HTML
MCPApp("ui://shop/card", Path("dist/card.html"))        # a built bundle, reread per read
MCPApp("ui://shop/card", Variable("card"))              # a request-scoped variable
MCPApp("ui://shop/card", render_card)                   # a sync or async callable
```

There is an overload per form, so an IDE shows you which one you are using.

**A path-like value is reread on every resource read.** Rebuild the bundle and the next read serves it; there is no cache to invalidate and no server to restart. A file that has gone missing fails that read with a message naming the path, rather than at construction — the document is only promised at read time.

```python linenums="1"
from pathlib import Path

from ag2.mcp import MCPApp

shop = MCPApp("ui://shop/card", Path(__file__).parent / "dist" / "card.html", inject_runtime=False)
```

### Request-scoped bodies and metadata

An app resolves runtime values from the same `context_provider` the conversational path uses, so a document is not a second dependency system. `content` may be a `Variable`, and a callable body may declare `Variable`, `Depends`/`Inject` and `MCPRequestContext` parameters exactly as a tool does:

```python linenums="1"
from dataclasses import dataclass
from typing import Annotated

from ag2 import Agent, Inject, Variable
from ag2.config import AnthropicConfig
from ag2.mcp import AskContext, MCPApp, MCPRequestContext, MCPServer

agent = Agent("shopkeeper", config=AnthropicConfig(model="claude-sonnet-5"))

@dataclass
class Branding:
    accent: str

async def provider(access) -> AskContext:
    return AskContext(variables={"tenant": "north"}, dependencies={"branding": Branding(accent="#0a7")})

async def card(
    tenant: Annotated[str, Variable("tenant")],
    branding: Annotated[Branding, Inject("branding")],
    ctx: MCPRequestContext,
) -> str:
    return f"<h1 style='color: {branding.accent}'>{tenant}</h1><div id='card'></div>"

shop = MCPApp("ui://shop/card", card, title=Variable("tenant"), listed=True)
server = MCPServer(agent, apps=[shop], context_provider=provider)
```

`title`, `description`, `inject_runtime`, the sandbox fields and the values inside `meta=` may each be a `Variable` too, resolved per request for the listing and the read.

!!! warning "The context is request-scoped, not turn-scoped"
    The host's document read and its tool call are **two separate MCP requests**, made in parallel. Each one calls your provider again and gets its own context; they share no mutable state. Do not use a variable to pass something from the call to the document — that is what `structuredContent` is for.

An ordinary `Resource` and an `@mcp_tool` resolve the same way, which is what keeps [taking an app apart](#taking-an-app-apart) honest.

### The document

```python linenums="1"
from pathlib import Path

from ag2.mcp import AppSandbox, MCPApp, ResourceCsp, ResourcePermissions

shop = MCPApp(
    "ui://shop/card",
    Path("dist/card.html"),
    title="Product card",
    description="A product card that can add its item to the cart.",
    listed=False,
    sandbox=AppSandbox(
        csp=ResourceCsp(connect_domains=["https://api.example.com"]),
        permissions=ResourcePermissions(camera={}),
        domain="https://shop.example.com",
    ),
    prefers_border=True,
)
```

- **`ui://` is required.** A host discards any other scheme, so a URI that is not `ui://` raises when the `MCPApp` is constructed, and two apps claiming one URI raise when the server is.
- **`listed` defaults to `False`.** The document stays out of `resources/list` — a person browsing a server's resources should not meet a file that is not one — while remaining readable by URI, which is how the host gets it. Set `listed=True` for a document meant to be discoverable.
- **The body has four forms** — inline HTML, a path-like bundle, a `Variable`, or a sync/async callable invoked per read. See [where the body comes from](#where-the-body-comes-from).
- **Sandbox policy is typed and grouped.** `csp`, `permissions` and `domain` travel together in `sandbox=AppSandbox(...)` and use the SDK's own models, so the wire spelling is never guessed at. They are also accepted as bare keywords for a one-field policy. `prefers_border` stays separate — it is a presentation hint, not a sandbox rule. `meta=` is a raw passthrough merged alongside, for whatever the specification adds next.
- **The `ui` slot behaves differently on a document and on a tool.** On the document it is shared, so a `ui` key inside `meta=` *merges over* the typed parameters above rather than being refused — the typed parameters are the spelling aid, not the authority. On a tool it is not shared: `@app.tool`'s `meta=` **rejects** a `ui` key outright, because the only thing in that slot is the binding the decorator itself writes. Pass `visibility=` instead, or declare the tool with `@mcp_tool` if it should not be bound to this document at all.

### Taking an app apart

An app is not a special kind of registration. `app.tools` are ordinary `MCPFunctionTool`s and `app.resource` is an ordinary `Resource`. With `agent` and `shop` from the snippet above, this:

```python linenums="1"
server = MCPServer(agent, apps=[shop])
```

is defined as shorthand for this:

```python linenums="1"
server = MCPServer(agent, tools=shop.tools, resources=[shop.resource])
```

Both produce the same tool list, the same resource listing, the same document and the same results — a test in the suite holds that equivalence so it cannot rot into a lie. Reach for the long form when you need an unusual arrangement; it is a rearrangement, not a rewrite.

Ordinary tools are unaffected throughout. A tool declared with `@mcp_tool` and passed in `tools=` behaves exactly as it did before apps existed, alongside any number of them.

**Registration closes the app's tool list.** Constructing the server is what reads `app.tools`, so a tool declared after that would exist and never be served. Declaring one raises `MCPAppFrozenError` (from `ag2.mcp.errors`) naming the tool, instead of leaving you to find it missing on the wire:

```python linenums="1"
server = MCPServer(agent, apps=[shop])

@shop.tool                      # MCPAppFrozenError: 'restock' cannot be declared on 'ui://shop/card'
async def restock() -> str: ...
```

The app itself stays reusable — registering the same one with a second server is fine; it is the composition that is closed, not the object.
