Topics that aren't part of the day-to-day A2A path: human-in-the-loop, transparent reconnects on streaming drops, plugging in a custom executor, and the error hierarchy.

## Human-in-the-Loop via `input_required`

When a server-side executor raises `#!python requires_input(...)` mid-task, the A2A server transitions the task to `#!python TASK_STATE_INPUT_REQUIRED` and surfaces the prompt to the client. The AG2 client invokes the local agent's `#!python hitl_hook` with the prompt and continues the same turn with the reply — the server prompt does **not** leak into the final response text.

```python linenums="1" hl_lines="4-5 10"
from ag2 import Agent
from ag2.a2a import A2AConfig

async def hitl_hook() -> str:
    return input("server asks input> ")

remote = Agent(
    "remote",
    config=A2AConfig(card_url="http://127.0.0.1:8000"),
    hitl_hook=hitl_hook,
)
reply = await remote.ask("start")  # server may request input multiple times
print(reply.response.content)
```

`#!python A2AConfig.input_required_timeout` caps how long the client waits on the hook. `#!python None` (default) waits indefinitely — which matches the behaviour of `#!python ConversationContext.input` in regular agents.

See [Human in the Loop](/docs/user-guide/context/human_in_the_loop) for the underlying `#!python hitl_hook` contract.

## Streaming Reconnect

Streaming connections drop. Network blips, load balancer recycles, idle timeouts — the SSE channel breaks, and the client needs to recover without losing partially-streamed artifacts.

The A2A client keeps internal drive state across drops: on `#!python A2AClientError` mid-stream it issues a fresh `#!python subscribe` against the same `#!python task_id` and continues from where it failed. The new stream opens with the task as it stands, so text produced while the client was disconnected is recovered from that snapshot. Artifacts are reconciled by `#!python artifact_id` (messages by `#!python message_id`): an update that restates what was already received adds nothing, and a completed artifact is never applied twice. Application code sees a single uninterrupted reply.

If the task finished while the stream was down, the server refuses the subscription; the client then reads the final task with `#!python get_task` and builds the reply from it, so a dropped connection at the very end does not fail the call.

The client can only resubscribe once it knows the task id, which arrives with the first event. A connection lost before that raises `#!python A2AReconnectError` without retrying: sending the message again would start a second task.

```python linenums="1" hl_lines="6-7"
remote = Agent(
    "remote",
    config=A2AConfig(
        card_url="http://127.0.0.1:8000",
        streaming=True,
        max_reconnects=3,
        reconnect_backoff=0.5,
    ),
)
reply = await remote.ask("a long answer")
```

| Field | Default | Purpose |
|---|---|---|
| `#!python max_reconnects` | `#!python 3` | Total reconnect attempts before giving up with `#!python A2AReconnectError` |
| `#!python reconnect_backoff` | `#!python 0.5` | Seconds to wait before the first attempt; doubles on each following one (no jitter) |

When attempts are exhausted the client raises `#!python A2AReconnectError(attempts=N)`. Catch it to fall back to a polling re-fetch via `#!python get_task` if you need recovery beyond the streaming budget.

## Custom `AgentExecutor`

`#!python A2AServer` defaults to wrapping the supplied `#!python Agent` in AG2's standard `#!python AgentExecutor`. When you need behaviour that doesn't fit `#!python Agent.ask` — a HITL-first turn, a multi-agent pipeline, a non-standard task lifecycle — drop in your own executor:

```python linenums="1" hl_lines="1 5-7 9-10 12"
from a2a.server.agent_execution import AgentExecutor as A2AAgentExecutorBase

from ag2.a2a import A2AServer

class MyExecutor(A2AAgentExecutorBase):
    async def execute(self, request_context, event_queue) -> None:
        ...

    async def cancel(self, request_context, event_queue) -> None:
        ...

server = A2AServer(agent_stub, executor=MyExecutor())
```

The executor owns the entire request lifecycle: parsing the inbound message, emitting status updates and artifacts to the `#!python event_queue`, and signalling terminal state. The wrapped agent passed to `#!python A2AServer(agent_stub, ...)` is still used for card metadata (`#!python name`, `#!python description`, etc.) — make it a stub if a real agent doesn't fit your design.

## Errors

All A2A errors live in `#!python ag2.a2a.errors` and inherit from `#!python A2AError`. Catch `#!python A2AError` for everything; catch the specifics when you want to react differently.

| Exception | Raised when |
|---|---|
| `#!python A2AError` | Base class — catch this for any A2A failure |
| `#!python A2AInvalidCardError` | The card is missing data required to connect (no `#!python supported_interfaces`, no usable URL) |
| `#!python A2AIncompatibleProtocolVersionError` | The interface AG2 selected declares an A2A protocol version older than 1.0 — `#!python err.protocol_version` and `#!python err.transport` hold what was advertised |
| `#!python A2AClientToolsNotSupportedError` | Client passed `#!python tools=` but the server card doesn't advertise the `#!python urn:ag2:client-tools:v1` extension |
| `#!python A2AExtensionNotSupportedError` | Client activated an extension URI the card doesn't advertise, or the card marks one `#!python required=True` that the client didn't activate — `#!python err.uris` holds the unreconciled URIs (see [Extensions](/docs/user-guide/a2a/client#extensions)) |
| `#!python A2ACardSignatureError` | A card failed JWS verification — `#!python err.source` says which card (see [Card Signing](/docs/user-guide/a2a/card_signing#failure-modes)) |
| `#!python A2AStaleCardSignatureError` | Server-side: a `#!python build_*` call was handed an already-signed card whose capability flags AG2 has to flip, with no `#!python card_signer` to re-sign it (see [Card Signing](/docs/user-guide/a2a/card_signing#bringing-your-own-signature)) |
| `#!python A2AReconnectError` | Streaming reconnect attempts exhausted — `#!python err.attempts` holds the count |
| `#!python A2ATaskTerminalError` | Base for the terminal-state errors below; carries `#!python err.task` with the final `#!python Task` (status, history, artifacts) |
| `#!python A2ATaskFailedError` | Task ended in `#!python TASK_STATE_FAILED` |
| `#!python A2ATaskRejectedError` | Task ended in `#!python TASK_STATE_REJECTED` |
| `#!python A2ATaskCancelledError` | Task ended in `#!python TASK_STATE_CANCELED` — `#!python err.task.artifacts` holds the partial text received before the cancellation |
| `#!python A2ATaskAuthRequiredError` | Task ended in `#!python TASK_STATE_AUTH_REQUIRED`. Per A2A spec §7.6 the agent expects credentials out-of-band — apply them and retry |

Catch `#!python A2ATaskTerminalError` to handle any terminal failure uniformly; switch on the concrete subclass when the recovery path differs (e.g. retry with auth on `#!python AuthRequired`, surface the error to the operator on `#!python Failed` / `#!python Rejected`, treat `#!python Cancelled` as an operator or server decision rather than a fault).

## Testing Helpers

`#!python ag2.a2a.testing` provides utilities for in-process A2A tests — no real socket, no port binding.

```python linenums="1" hl_lines="6-7"
from ag2 import Agent
from ag2.a2a import A2AConfig, A2AServer
from ag2.a2a.testing import make_test_client_factory

server = A2AServer(agent)
factory = make_test_client_factory(server, url="http://test")
remote = Agent("remote", config=A2AConfig(card_url="http://test", httpx_client_factory=factory))
await remote.ask("ping")
```

| Helper | Purpose |
|---|---|
| `#!python make_test_client_factory(server, url=..., card=..., timeout=...)` | `#!python httpx.AsyncClient` factory dispatching JSON-RPC into the server's ASGI app via `#!python httpx.ASGITransport` |
| `#!python make_test_rest_client_factory(server, url=..., card=..., timeout=...)` | Same idea for REST — builds the REST app and a card declaring only the REST interface |
| `#!python pick_free_port(host="127.0.0.1")` | Probe a free TCP port. Used by gRPC tests since gRPC has no in-process transport equivalent |
| `#!python ToolRoundsConfig(*rounds)` | Script a served agent one tool round at a time — a `#!python Turn`, or a `#!python TestConfig` for a round that streams before it ends — for tests where the client runs tools and the server continues the task |
| `#!python ObservedAgentExecutor(agent, *observers)` | Serve `#!python agent` with observers that see the request's whole task lifecycle, including `#!python WORKING` and the terminal status, which observers on the agent miss because they only run during the model turn. They see what this request puts on the wire: a task parked in `#!python INPUT_REQUIRED` and cancelled afterwards, or one cancelled through another replica, is closed by the SDK outside the request, so read its final state with `#!python get_task` |
| `#!python TaskStatusRecorder()` | Observer recording every `#!python A2ATaskStatusUpdate` state in delivery order; `#!python await recorder.wait_for(state)` waits for one |
| `#!python TurnGate()` | A server tool, `#!python gate.hold`, that keeps the task `#!python working` until `#!python gate.release()`, so a test can cancel or inspect it mid-turn |

The server builds a fresh LLM client for every request, so a single `#!python TestConfig` would replay its first turn after each client-tool round trip. `#!python ToolRoundsConfig` picks the round from the conversation history instead:

```python linenums="1"
from ag2 import Agent
from ag2.a2a.testing import ToolRoundsConfig
from ag2.events import ToolCallEvent

server_agent = Agent(
    "server",
    config=ToolRoundsConfig(
        ToolCallEvent(name="get_weather", arguments='{"city": "Paris"}'),  # round 1: call the client tool
        "Sunny in Paris.",  # round 2: answer after the tool result
    ),
)
```

To assert on the server side of a task's lifecycle, serve the agent through `#!python ObservedAgentExecutor`:

```python linenums="1"
import asyncio

from a2a.types import TaskState

from ag2 import Agent
from ag2.a2a import A2AConfig, A2AServer
from ag2.a2a.tasks import cancel_task, list_tasks
from ag2.a2a.testing import ObservedAgentExecutor, TaskStatusRecorder, TurnGate, make_test_client_factory
from ag2.events import ToolCallEvent
from ag2.testing import TestConfig

gate = TurnGate()
statuses = TaskStatusRecorder()
agent = Agent("server", config=TestConfig(ToolCallEvent(name="hold"), "done"), tools=[gate.hold])
server = A2AServer(agent, executor=ObservedAgentExecutor(agent, statuses))
config = A2AConfig(card_url="http://test", httpx_client_factory=make_test_client_factory(server))
remote = Agent("remote", config=config)

asking = asyncio.create_task(remote.ask("go"))
await gate.entered.wait()  # the task is working
[task] = (await list_tasks(config)).tasks
await cancel_task(config, task.id)

assert statuses.states == [TaskState.TASK_STATE_WORKING, TaskState.TASK_STATE_CANCELED]
```

Pass `#!python card=` when the default `#!python build_card(agent, url=url)` can't express what the test needs — a custom `#!python extensions` list, for instance. It defaults to `#!python None`, which keeps the auto-built card.

```python linenums="1"
from ag2.a2a.testing import pick_free_port

port = pick_free_port()
grpc_server = server.build_grpc(bind=f"127.0.0.1:{port}", grpc_url=f"grpc://127.0.0.1:{port}")
```
