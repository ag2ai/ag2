`#!python A2AServer` wraps an existing `#!python Agent` and produces a transport object you can serve directly. JSON-RPC is the default; the same `#!python A2AServer` instance can also build REST and gRPC transports that share one task store.

## Minimal Server

The smallest end-to-end setup: an `#!python Agent` with a tool, served over JSON-RPC on a single port via `uvicorn`.

```python linenums="1"
import uvicorn

from ag2 import Agent
from ag2.a2a import A2AServer, build_card
from ag2.config import AnthropicConfig
from ag2.tools import tool

@tool(description="Add two integers and return the sum as a string.")
async def calc_add(a: int, b: int) -> str:
    return f"{a + b}"

async def main() -> None:
    agent = Agent(
        name="claude",
        config=AnthropicConfig(model="claude-sonnet-5"),
        tools=[calc_add],
    )
    server = A2AServer(agent)
    card = build_card(agent, url="http://127.0.0.1:8000")
    asgi = server.build_jsonrpc(url="http://127.0.0.1:8000", card=card)

    await uvicorn.Server(uvicorn.Config(asgi, host="127.0.0.1", port=8000)).serve()

```

After startup the agent card is reachable at `#!python http://127.0.0.1:8000/.well-known/agent-card.json`. A client connects by passing that base URL to `#!python A2AConfig(card_url=...)` — see the [Client](/docs/user-guide/a2a/client) page.

## What `A2AServer` Holds

`#!python A2AServer.__init__` materialises transport-agnostic state — the executor, the task store, optional push notifications. Transport-specific parameters (URL, paths, ports) live on the `#!python build_*` methods.

| Constructor argument | Purpose |
|---|---|
| `#!python agent` | The AG2 `#!python Agent` exposed over A2A |
| `#!python task_store` | Shared `#!python TaskStore`, or a `#!python VersionedTaskStore` for [several replicas](#running-on-several-replicas). Defaults to a single `#!python InMemoryTaskStore` reused across every `#!python build_*` call |
| `#!python event_stream` | `#!python TaskEventStream` that carries task events between replicas. Required with a `#!python VersionedTaskStore`, rejected without one |
| `#!python push_config_store` | Enables push-notifications CRUD (see [Tasks & Push](/docs/user-guide/a2a/tasks_and_push)). Optional |
| `#!python push_sender` | Custom delivery sender. Defaults to no-op when not set |
| `#!python push_url_validator` | Optional async callback receiving a URL and returning `bool`. Rejects disallowed push-notification URLs before storing them |
| `#!python extended_card` | Auth-aware extra metadata returned via `#!python GetExtendedAgentCard` |
| `#!python card_modifier` / `#!python extended_card_modifier` | Per-request hooks that mutate the card before it's served |
| `#!python card_signer` | Attaches a JWS signature to every card served, on all transports (see [Card Signing](/docs/user-guide/a2a/card_signing)). Optional |
| `#!python executor` | Escape hatch — drop in a custom `#!python AgentExecutor` (see [Advanced](/docs/user-guide/a2a/advanced#custom-agentexecutor)) |

#### Safe push notifications

With push notifications the server POSTs task updates to a webhook URL **that
the client chooses**. A client can therefore point the server at internal
addresses or cloud metadata endpoints (SSRF). Protect the server with a URL
policy.

**Server.** Enable push with a store and pass `#!python push_url_validator`. The
SDK ships a ready-made policy, `#!python validate_push_notification_url`, that
allows only public `http(s)` hosts. You pass the function itself (no call, no
URL); the SDK calls it with the client's URL on every registration:

```python linenums="1"
from a2a.server.tasks import InMemoryPushNotificationConfigStore
from a2a.utils.push_url_validator import validate_push_notification_url

from ag2.a2a import A2AServer

server = A2AServer(
    agent,
    push_config_store=InMemoryPushNotificationConfigStore(),
    push_url_validator=validate_push_notification_url,
)
```

**Client.** The URL is set by whoever registers the webhook, using the helpers
from [Tasks & Push](/docs/user-guide/a2a/tasks_and_push):

```python linenums="1"
from ag2.a2a import A2AConfig
from ag2.a2a.push import A2APushConfig, create_push_notification_config

client = A2AConfig(card_url="http://127.0.0.1:8000")

await create_push_notification_config(
    client, task_id, A2APushConfig(url="https://my-app.example.com/a2a-hook")
)  # accepted

await create_push_notification_config(
    client, task_id, A2APushConfig(url="http://169.254.169.254/latest/meta-data")
)  # raises InvalidParamsError, nothing is stored
```

Pass your own `#!python async def check(url: str) -> bool` instead to apply a
different policy, for example an allow-list of partner hosts. A rejected URL
fails registration with the SDK's invalid-params error on JSON-RPC, REST, and
gRPC.

- **Off by default.** Without `#!python push_url_validator` any URL is accepted,
  as before; AG2 does not choose a policy for you.
- **Needs a store.** `#!python push_url_validator` without `#!python push_config_store`
  raises `#!python ValueError`, because push is disabled without a store.
- **Hosts must resolve.** The SDK policy resolves the hostname and rejects it if
  DNS fails or any address is private, loopback, or link-local. The client only
  sees `Invalid push notification URL`; the reason is in the server log.
- **Registration only.** The validator screens URLs when they are registered. A
  custom `#!python push_sender` is not covered; give it the same callback (the
  SDK's `#!python BasePushNotificationSender` takes `#!python push_url_validator`).
- Works on every SDK `ag2[a2a]` installs (`a2a-sdk>=1.2.0`).

!!! note
    The default `#!python InMemoryTaskStore` is materialised **once** at `#!python __init__` time. This is what makes JSON-RPC, REST and gRPC bound to the same `#!python A2AServer` see each other's tasks — a single store, three transports.

## Running on Several Replicas

By default a task lives in the memory of the process that started it, so a second copy of the server answers `#!python GetTask` with "not found". To run the same agent behind a load balancer, give every replica one shared **versioned task store** (concurrent writers are detected instead of overwritten) and one **event stream** (a client that subscribes through one replica receives the events of a task running on another). The SDK ships SQL implementations of both; install the driver for your database through the SDK's own extras, for example `pip install "a2a-sdk[postgresql]"`. `ag2[a2a]` adds no database dependency.

```python linenums="1"
from a2a.server.cluster import DatabaseTaskEventStream, VersionedDatabaseTaskStore
from sqlalchemy.ext.asyncio import create_async_engine

from ag2.a2a import A2AServer

engine = create_async_engine("postgresql+asyncpg://user:password@db/a2a")
task_store = VersionedDatabaseTaskStore(engine)
event_stream = DatabaseTaskEventStream(engine)

# Create the tables once at startup, before serving. The SDK creates only the
# `tasks` table on first use; without these calls the first request fails with
# `no such table: task_versions`.
await task_store.initialize()
await event_stream.initialize()

server = A2AServer(agent, task_store=task_store, event_stream=event_stream)
app = server.build_jsonrpc(url="https://my-agent.example.com")
```

Run the same code in every replica. JSON-RPC, REST and gRPC built from one server share both objects. The load balancer needs no sticky routing: AG2's executor keeps no per-task state between calls, so a task that paused for a client-side tool call or for human input can be resumed on a different replica.

`#!python A2AServer` refuses a configuration that cannot work, at construction time:

- A `#!python VersionedTaskStore` **without** `#!python event_stream` raises `#!python ValueError`. Without a stream, streaming would silently work only on the replica running the task. A single replica that uses a versioned store passes a stream too.
- An `#!python event_stream` **without** a `#!python VersionedTaskStore` raises `#!python ValueError`: the stream orders events by task version.

!!! warning "Push notifications stay per-replica"
    `#!python push_config_store` and `#!python push_sender` are separate from the task store and are **not** shared by the setup above. With the default in-memory push store, a webhook registered through replica A is unknown to replica B, so a task that finishes on B sends nothing and raises no error. If webhooks must work across replicas, pass the SDK's database push store, built on the same engine, and a sender that reads it:

    ```python linenums="1"
    from a2a.server.tasks import BasePushNotificationSender, DatabasePushNotificationConfigStore

    push_store = DatabasePushNotificationConfigStore(engine)
    await push_store.initialize()

    server = A2AServer(
        agent,
        task_store=task_store,
        event_stream=event_stream,
        push_config_store=push_store,
        push_sender=BasePushNotificationSender(http_client, push_store),
    )
    ```

    AG2 does not warn about an in-memory push store: it is a valid choice when webhooks only need to work on one replica.

## Server-side Tools

Tools attached to the wrapped `#!python Agent` execute on the server, just as they would for a local agent. The remote LLM picks them up automatically.

```python linenums="1" hl_lines="10-13"
from ag2 import Agent
from ag2.a2a import A2AServer
from ag2.config import AnthropicConfig
from ag2.tools import tool
from ag2.tools.builtin import WebSearchTool

agent = Agent(
    name="claude",
    config=AnthropicConfig(model="claude-sonnet-5"),
    tools=[
        WebSearchTool(),  # built-in provider tool — runs on Anthropic's side
        calc_add,         # @tool — runs on this server
    ],
)
server = A2AServer(agent)
```

For client-side tools — declared on the *caller* and forwarded back from the server when the LLM calls them — see [Client → Local Tools](/docs/user-guide/a2a/client#local-tools-forwarded-from-the-server).

## Choosing a Transport

The default `#!python build_jsonrpc(...)` is the right choice for most setups. JSON-RPC is the most widely-supported A2A binding, works over any HTTP infrastructure (proxies, gateways, load balancers), and is what every A2A client implementation speaks first.

Reach for an alternative transport when:

| Transport | Use when |
|---|---|
| `#!python build_jsonrpc` (default) | You want the simplest, most portable HTTP binding. Recommended start. |
| `#!python build_rest` | You need a HTTP+JSON REST surface with stable URLs (logging, cache control, route-level auth in a gateway). |
| `#!python build_grpc` | You need bidirectional streaming with low overhead, or your infra is gRPC-native. |

### REST

```python linenums="1"
card = build_card(agent, url="http://127.0.0.1:8001", transports=("rest",))
rest_app = server.build_rest(url="http://127.0.0.1:8001", card=card)
await uvicorn.Server(uvicorn.Config(rest_app, host="127.0.0.1", port=8001)).serve()
```

`#!python build_rest(path_prefix="/v1")` mounts the routes under a sub-path; both the card and the dispatcher respect it.

### gRPC

```python linenums="1"
card = build_card(
    agent,
    url="grpc://127.0.0.1:50051",
    transports=("grpc",),
    grpc_url="grpc://127.0.0.1:50051",
)
grpc_server = server.build_grpc(
    bind="127.0.0.1:50051",
    grpc_url="grpc://127.0.0.1:50051",
    card=card,
)
await grpc_server.start()
await grpc_server.wait_for_termination()
```

`#!python build_grpc` returns an unstarted `#!python grpc.aio.Server` — the caller is responsible for `#!python start()` and `#!python wait_for_termination()`. `#!python bind` is the listener address, `#!python grpc_url` is the URL declared in the card (they're usually identical, but differ when the server sits behind a load balancer).

!!! note
    A2A v1.x has no `#!python GetAgentCard` gRPC method — the public card is always served over HTTP at `#!python /.well-known/agent-card.json`. So even for a gRPC-only server clients fetch the card via HTTP first, then switch to gRPC for the actual exchange. Plan your card URL accordingly.

#### TLS

`#!python build_grpc` binds an insecure port by default for backwards compatibility. Pass a `#!python grpc.ServerCredentials` object as `#!python server_credentials=` to bind a secure port, and publish the interface with a `#!python grpcs://` or `#!python grpc+tls://` URL:

```python linenums="1" hl_lines="7-9 11-18"
from pathlib import Path

import grpc

from ag2.a2a import build_card

private_key = Path("certs/server-key.pem").read_bytes()
certificate = Path("certs/server.pem").read_bytes()
credentials = grpc.ssl_server_credentials([(private_key, certificate)])

grpc_url = "grpcs://agents.example.com:50051"
card = build_card(agent, url="https://agents.example.com", transports=("grpc",), grpc_url=grpc_url)
grpc_server = server.build_grpc(
    bind="0.0.0.0:50051",
    grpc_url=grpc_url,
    card=card,
    server_credentials=credentials,
)
await grpc_server.start()
await grpc_server.wait_for_termination()
```

AG2 does not read certificate files or alter the credentials; certificate loading, rotation and mTLS policy remain under application control. To require client certificates, create the server credentials with `#!python root_certificates=<client CA>` and `#!python require_client_auth=True`. See [gRPC TLS on the client](/docs/user-guide/a2a/client#grpc-tls) for public-CA, private-CA and mTLS channels.

### One Server, Three Transports

The same `#!python A2AServer` instance can back any combination of transports. Build a single multi-transport `#!python AgentCard` and call each `#!python build_*` against it — they share one task store.

```python linenums="1" hl_lines="7-9 12-14"
from a2a.server.tasks import InMemoryPushNotificationConfigStore

server = A2AServer(agent, push_config_store=InMemoryPushNotificationConfigStore())
card = build_card(
    agent,
    url="http://127.0.0.1:8000",
    transports=("jsonrpc", "rest", "grpc"),
    rest_url="http://127.0.0.1:8001",
    grpc_url="grpc://127.0.0.1:50051",
)

asgi = server.build_jsonrpc(url="http://127.0.0.1:8000", card=card)
rest = server.build_rest(url="http://127.0.0.1:8001", card=card)
grpc = server.build_grpc(bind="127.0.0.1:50051", grpc_url="grpc://127.0.0.1:50051", card=card)

await grpc.start()
await asyncio.gather(
    uvicorn.Server(uvicorn.Config(asgi, host="127.0.0.1", port=8000)).serve(),
    uvicorn.Server(uvicorn.Config(rest, host="127.0.0.1", port=8001)).serve(),
    grpc.wait_for_termination(),
)
```

## Customising the `AgentCard`

`#!python build_card(agent, url=...)` accepts a handful of optional kwargs to enrich the published card with discovery metadata and auth declarations.

| Argument | Purpose |
|---|---|
| `#!python version` | Card version (defaults to `#!python "1.0.0"`) |
| `#!python description` | Free-form description. Defaults to the first entry of the agent's system prompt |
| `#!python skills` | Explicit `#!python Sequence[AgentSkill]`. When `#!python None`, `#!python build_card` walks `#!python agent.tools` for any `#!python SkillsToolkit` and publishes its local skills automatically; falls back to a single agent-derived skill if none are found |
| `#!python push_notifications` | Toggles `#!python capabilities.push_notifications` on the card |
| `#!python provider` | `#!python AgentProvider` block (organization, URL) |
| `#!python documentation_url` / `#!python icon_url` | Discovery metadata |
| `#!python security` | Auth declarations — see below |
| `#!python extensions` | `#!python Sequence[AgentExtension]` — protocol extensions to declare alongside AG2's own; see below |
| `#!python tenants` | `#!python Mapping[TransportName, str]` — surface a per-transport tenant on the corresponding `#!python AgentInterface.tenant` |
| `#!python rest_url` / `#!python rest_path_prefix` / `#!python grpc_url` | Per-transport URL overrides for multi-transport cards |

### Declaring Authentication

`#!python ag2.a2a.security` ships factories for every A2A-recognised scheme. Each factory returns a typed `#!python Scheme` object that carries its card-level binding name. Pass them to `#!python require(...)` to build `#!python Requirement` entries; `#!python build_card` auto-derives the card's `#!python security_schemes` from the schemes referenced in `#!python security=` — no duplicate declarations.

```python linenums="1" hl_lines="8-9 14"
from ag2.a2a import A2AServer, build_card
from ag2.a2a.security import (
    bearer_scheme,
    api_key_scheme,
    require,
)

bearer = bearer_scheme(name="bearer", bearer_format="JWT")
api_key = api_key_scheme(name="x_api_key", key_name="X-API-Key", location="header")

card = build_card(
    agent,
    url="http://127.0.0.1:8000",
    security=[require(bearer), require(api_key)],
)
```

| Helper | Scheme |
|---|---|
| `#!python bearer_scheme(name=..., bearer_format=..., description=...)` | HTTP Bearer (e.g. JWT) |
| `#!python http_auth_scheme(name=..., scheme=..., ...)` | Any other HTTP auth scheme (basic, digest, custom bearer formats) |
| `#!python api_key_scheme(name=..., key_name=..., location=...)` | API key in header / query / cookie. `#!python name` is the card binding; `#!python key_name` is the header/query/cookie key sent by the client. |
| `#!python oauth2_scheme(name=..., flows=..., oauth2_metadata_url=...)` | OAuth2 wrapping a pre-built `#!python OAuthFlows` |
| `#!python open_id_connect_scheme(name=..., url=...)` | OpenID Connect discovery URL |
| `#!python mtls_scheme(name=...)` | Mutual TLS client-cert auth |

#### Combining requirements: AND vs OR

The `#!python security=` list holds independent rules — clients only need to satisfy **one** of them (entries are OR-ed). Inside a single `#!python require(...)` call, **all** passed schemes must be presented together (arguments are AND-ed). Attach OAuth2/OIDC scopes via `#!python scheme.with_scopes(...)`.

**Example A — accept Bearer OR API-key** (two separate `#!python require()` calls):

```python linenums="1"
security=[
    require(bearer),
    require(api_key),
]
```

| Request headers | Accepted? |
|---|---|
| `#!python Authorization: Bearer <jwt>` | ✅ matches first rule |
| `#!python X-API-Key: <key>` | ✅ matches second rule |
| both headers present | ✅ either rule alone is enough |
| neither | ❌ no rule satisfied |

**Example B — require Bearer AND API-key together** (one `#!python require()` with two args):

```python linenums="1"
security=[
    require(bearer, api_key),
]
```

| Request headers | Accepted? |
|---|---|
| only `#!python Authorization: Bearer <jwt>` | ❌ missing API key |
| only `#!python X-API-Key: <key>` | ❌ missing Bearer |
| both headers present | ✅ both args inside the same `#!python require()` satisfied |

**Example C — mixing scopes** (OAuth2 needs scopes, Bearer doesn't):

```python linenums="1"
security=[
    require(bearer, oauth.with_scopes("read", "write")),
]
```

Scheme binding names are arbitrary strings — pass any value to `#!python name=`, including non-identifier forms like `#!python "X-My-Scheme"`:

```python linenums="1"
custom = bearer_scheme(name="X-My-Scheme")
require(custom)
```

!!! note
    `#!python build_card` only **declares** auth on the card — it does not enforce it. Wire the actual check into the ASGI app (Starlette middleware, gateway, reverse proxy) or the gRPC server's interceptors.

### Declaring Extensions

A2A extensions let an agent advertise protocol behaviour beyond the base spec. AG2 always declares its own `#!python urn:ag2:client-tools:v1` as `#!python required=False`; pass `#!python extensions=` to declare your own alongside it.

```python linenums="1" hl_lines="8-14"
from a2a.types import AgentExtension

from ag2.a2a import build_card

card = build_card(
    agent,
    url="http://127.0.0.1:8000",
    extensions=[
        AgentExtension(
            uri="urn:acme:billing:v1",
            description="Attaches a cost breakdown to every reply",
            required=True,
        ),
    ],
)
```

`#!python required=True` declares that the exchange genuinely breaks without the extension. AG2's *client* honours the flag: it refuses to connect to a card requiring a URI it hasn't activated, rather than proceeding and misbehaving mid-task. Note this is client-side only — `#!python build_card` declares the requirement, it does not enforce it, and a client that ignores the flag is still served. Use `#!python required=False` to let extension-unaware clients keep working.

Duplicate URIs raise `#!python ValueError`, including redeclaring `#!python urn:ag2:client-tools:v1` — `#!python build_card` always declares that one itself, so a card can never ship two entries for the same extension.

See [Extensions](/docs/user-guide/a2a/client#extensions) for activating them on the client.

## Conversation Variables

The caller's message can carry a variables payload, which is merged into the served turn's
variables before the agent runs, and the turn's variables travel back on the reply. Treat
them as caller-writable and caller-readable: anything the caller should not set or see
belongs in `#!python dependencies`, which are never synced. Keys under the reserved
`#!python ag:` / `#!python a2a:` prefixes are stripped in both directions. See
[Variables over a protocol connection](/docs/user-guide/context/variables#variables-over-a-protocol-connection).

## Adding Cross-cutting Middleware

A2A doesn't define server-side middleware. Attach CORS, auth or tracing directly to the returned transport object:

```python linenums="1" hl_lines="4"
from starlette.middleware.cors import CORSMiddleware

asgi = server.build_jsonrpc(url="http://127.0.0.1:8000")
asgi.add_middleware(CORSMiddleware, allow_origins=["*"])
```

For gRPC, attach interceptors when constructing the channel via `#!python grpc.aio.Server` options on `#!python build_grpc(options=...)`.
