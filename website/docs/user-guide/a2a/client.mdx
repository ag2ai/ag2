`#!python A2AConfig` is a `#!python ModelConfig` — pass it to a regular `#!python Agent` and the remote A2A server becomes that agent's LLM provider. Conversation history, tool calls and streaming are negotiated through the protocol; calling code keeps the familiar `#!python agent.ask(...)` / `#!python reply.ask(...)` shape.

## Minimal Client

```python linenums="1"
from ag2 import Agent
from ag2.a2a import A2AConfig

async def main() -> None:
    remote = Agent(
        "remote",
        config=A2AConfig(card_url="http://127.0.0.1:8000"),
    )
    reply = await remote.ask("Add 17 and 25 with calc_add. Just the number.")
    print(reply.response.content)  # -> "42"

```

`#!python card_url` is the HTTP(S) base where the server publishes `#!python /.well-known/agent-card.json`. The client fetches the card on first use, picks a binding from `#!python supported_interfaces`, and uses the URL declared in the card for every subsequent request — you don't pass transport-specific URLs.

## Selecting a Transport

When the card declares multiple bindings, `#!python prefer=...` forces a choice:

```python linenums="1" hl_lines="3"
config = A2AConfig(
    card_url="http://127.0.0.1:8000",
    prefer="grpc",  # one of "jsonrpc" | "rest" | "grpc"
)
```

`#!python prefer=None` (default) auto-picks: if exactly one declared interface URL matches `#!python card_url` it wins; otherwise the first server-listed interface is used.

!!! tip
    `#!python card_url` is always an HTTP URL — even when the resolved transport is gRPC. The card is served over HTTP per spec; only the actual message exchange uses the resolved binding.

## gRPC TLS

The default gRPC channel factory selects security from the interface URL published in the agent card. `#!python grpcs://` and `#!python grpc+tls://` create a TLS channel using the system CA roots; `#!python grpc://`, `#!python grpc+insecure://` and a bare `#!python host:port` keep the backwards-compatible insecure channel.

For a server certificate issued by a public CA, the client needs no TLS-specific configuration. It fetches the card over HTTPS and follows the secure gRPC interface declared there:

```python linenums="1" hl_lines="7"
from ag2 import Agent
from ag2.a2a import A2AConfig

remote = Agent(
    "remote",
    config=A2AConfig(
        card_url="https://agents.example.com",
        prefer="grpc",
    ),
)
reply = await remote.ask("Summarize the latest report.")
```

Private CAs, self-signed certificates and mTLS need custom `#!python grpc.ChannelCredentials`. Wrap those credentials with `#!python secure_grpc_channel_factory(...)` and pass the returned callable through the existing `#!python grpc_channel_factory` escape hatch:

```python linenums="1" hl_lines="7-8 11-16"
from pathlib import Path

import grpc

from ag2 import Agent
from ag2.a2a import A2AConfig, secure_grpc_channel_factory

ca_certificate = Path("certs/ca.pem").read_bytes()
credentials = grpc.ssl_channel_credentials(root_certificates=ca_certificate)
remote = Agent(
    "remote",
    config=A2AConfig(
        card_url="https://agents.internal.example",
        prefer="grpc",
        grpc_channel_factory=secure_grpc_channel_factory(credentials),
    ),
)
reply = await remote.ask("Run the internal health check.")
```

The secure factory always creates a TLS channel, regardless of whether the card uses a secure, insecure or bare gRPC URL spelling. It also accepts gRPC channel options via `#!python options=`. For mTLS, construct the credentials with `#!python root_certificates=`, `#!python private_key=` and `#!python certificate_chain=`; AG2 passes the resulting object to gRPC unchanged.

!!! warning
    TLS protects the gRPC connection only. Card discovery is a separate HTTP request, so publish the card over HTTPS as well and keep `#!python card_url` on that HTTPS origin.

## Multi-turn — `reply.ask`

A2A servers are stateless from AG2's perspective: every call ships the full conversation history as a `#!python application/vnd.ag2.history+json` `#!python DataPart` attached to the outgoing message. The continuation API is the regular `#!python reply.ask(...)`:

```python linenums="1"
remote = Agent("remote", config=A2AConfig(card_url="http://127.0.0.1:8000"))

reply = await remote.ask("Remember the number 42.")
reply = await reply.ask("What number did I ask you to remember?")
print(reply.response.content)
```

The remote agent recovers the entire prior context on every turn — there is no server-side session id to manage.

## Conversation Variables

Every request also carries the conversation's variables to the server, and the server's
reply carries its own back — merged into the calling turn before the local tools run. So
a variable is readable and writable by the remote end; keep anything the peer should not
see or set in `#!python dependencies`, which are never synced. Keys under the reserved
`#!python ag:` / `#!python a2a:` prefixes are stripped in both directions. See
[Variables over a protocol connection](/docs/user-guide/context/variables#variables-over-a-protocol-connection).

## Local Tools (forwarded from the server)

Tools declared on the **client** are advertised to the server in the AG2 client-tools extension. When the remote LLM picks one, the call is routed back to the client and executed locally; the tool result is sent back into the server-side LLM loop. The server LLM never sees your local environment.

```python linenums="1" hl_lines="7-9 14"
from datetime import datetime

from ag2 import Agent
from ag2.a2a import A2AConfig
from ag2.tools import tool

@tool(description="Return the user's local wall-clock time as ISO-8601.")
def get_local_time() -> str:
    return datetime.now().isoformat(timespec="seconds")

remote = Agent(
    "remote",
    config=A2AConfig(card_url="http://127.0.0.1:8000"),
    tools=[get_local_time],
)
reply = await remote.ask("What time is it on my machine? Use get_local_time.")
```

The same agent can mix client-side and server-side tools — server tools execute remotely, client tools execute locally, and the LLM picks freely between them within one turn. A client tool never replaces a server tool with the same name: the server keeps its own tool and drops the client one with a warning.

!!! warning
    If the remote `#!python AgentCard` does not advertise the `#!python urn:ag2:client-tools:v1` extension, passing `#!python tools=...` raises `#!python A2AClientToolsNotSupportedError`. Only AG2-backed servers support client-side tool forwarding today.

## Remote Agent as a Sub-tool — `as_tool()`

A remote A2A agent plugs into a local `#!python Agent` like any other delegate via `#!python Agent.as_tool()`. The local LLM decides when to delegate; the wrapper exposes a `#!python task_<name>` tool that takes an `objective` (and optional `context`).

```python linenums="1" hl_lines="14"
from ag2 import Agent
from ag2.a2a import A2AConfig
from ag2.config import AnthropicConfig

researcher = Agent(
    "researcher",
    config=A2AConfig(card_url="http://research.internal:8000"),
)

writer = Agent(
    "writer",
    prompt="Use the researcher tool to gather facts before writing a draft.",
    config=AnthropicConfig(model="claude-sonnet-5"),
    tools=[researcher.as_tool(description="Delegate research questions to the remote researcher.")],
)

reply = await writer.ask("Write a 3-paragraph brief on the latest A2A spec changes.")
```

This composes naturally with several remotes — give each `#!python as_tool()` a distinct `name=` and let the local LLM route by capability. See [Subagents](/docs/user-guide/subagents) for the general `#!python as_tool()` semantics.

!!! note
    Each `#!python task_<name>` call spawns a fresh sub-agent stream; history between calls is not preserved on the sub-task side. For a remote that remembers prior turns, prefer the `#!python reply.ask(...)` pattern above instead of `#!python as_tool()`.

## Extensions

A2A extensions are activated **per connection** by URI. List them on `#!python A2AConfig.extensions`; every URI must be advertised in the server card's `#!python capabilities.extensions`.

```python linenums="1" hl_lines="6"
from ag2 import Agent
from ag2.a2a import A2AConfig

remote = Agent(
    "remote",
    config=A2AConfig(card_url="http://127.0.0.1:8000", extensions=["urn:acme:billing:v1"]),
)
reply = await remote.ask("invoice summary for Q3")
```

Activated URIs travel on both channels the spec allows — the `#!python Message.extensions` field and the `#!python A2A-Extensions` header (gRPC metadata on the gRPC binding) — and stay attached across continuation legs, so a tool-result or HITL round-trip does not silently deactivate them mid-task.

The card and the activation list are reconciled before the first request goes out, so a mismatch surfaces as `#!python A2AExtensionNotSupportedError` at connect time instead of an opaque failure mid-task. It is raised in both directions:

- a URI the card does not advertise — a client-side mistake;
- an extension the card marks `#!python required=True` that the client did not activate — the server expects behaviour AG2 will not provide.

`#!python urn:ag2:client-tools:v1` is the exception to the second rule: AG2 implements it natively, so a card may require it without the client listing it explicitly.

Activation covers every request the config makes, not just `#!python ask`. The one-shot [task](/docs/user-guide/a2a/tasks_and_push) and push-notification helpers open their own connection from the same `#!python A2AConfig`, so they activate the same URIs and run the same reconciliation — a server enforcing a `#!python required=True` extension sees a consistent client on the conversational and the administrative path alike.

```python linenums="1" hl_lines="5-6"
from ag2.a2a.errors import A2AExtensionNotSupportedError

try:
    await remote.ask("invoice summary for Q3")
except A2AExtensionNotSupportedError as err:
    print(err.uris)  # the URIs that could not be reconciled
```

See [Declaring Extensions](/docs/user-guide/a2a/server#declaring-extensions) for the server side.

## What the Reply Contains

The reply is the text of the final model turn; text from earlier turns of a tool round trip is not repeated. Each artifact's text appears once, including an artifact that carries other parts next to its text. Artifacts are ordered by when they first appeared on the task, which is the order a polled task lists them, so an artifact reused from an earlier turn of a tool round trip comes before one that this turn added. The text of a message answering the turn follows the artifacts. A text artifact the server re-sends in full replaces its earlier content instead of being appended to it, even when the new text is shorter. A tool call is surfaced once however often later updates or polls repeat it.

<!-- Pending maintainer agreement (PR #3494, Open Decision 1): the reading of a re-send into a reused artifact id below is proposed, not settled. Keep it in step with the _ArtifactText docstring. -->

When a server writes into an artifact id it already used in an earlier turn, the reply holds only what the artifact gained in this turn: its text past what it held when the turn began, or its whole text if it no longer begins with that. An artifact that comes back unchanged adds nothing. A full re-send that begins with the earlier turn's text therefore counts as a continuation of it, because a polled snapshot of appended text looks exactly the same. A server that wants a whole new answer in a later turn should write it to a new artifact id, as the AG2 server does.

When the server cancels the task, the client raises `#!python A2ATaskCancelledError` with the text received so far in `#!python err.task.artifacts`, one entry per artifact under its own id. Only a completed task's status message is part of the reply; a message attached to a task that is still working is a progress note and is left out, and one that repeats the artifacts' text exactly is not counted twice. A completion message with other text is appended after the artifacts' text exactly as sent, with no separator added. An AG2 server returns its answer as a text artifact, as the A2A spec asks of results, whether or not the model streamed it, so its text never arrives twice, even when the server ran its own tools between model calls; its completion message carries only context variables. Client tools run only when the task waits for input: a tool call on a task that completes is logged and ignored, since a finished task takes no tool results. Polling and streaming follow the same rules.

A streamed task can reach its final state without a separate status update: the stream may consist of the task alone, already finished, or close on a final task snapshot. The client reads the outcome from that task, so a cancelled, failed or rejected task raises its error either way. If the stream closes before the task has reached a final state, which can happen when a cancel is recorded after the server has stopped streaming, the client reads the task with `#!python get_task` until it settles instead of returning the partial text as the answer.

## A2AConfig Reference

| Field | Type | Default | Purpose |
|---|---|---|---|
| `card_url` | `#!python str` | required | Base URL where `#!python /.well-known/agent-card.json` is served |
| `prefer` | `#!python Optional[Literal["jsonrpc", "rest", "grpc"]]` | `#!python None` | Force a specific binding when the card declares more than one |
| `streaming` | `#!python bool` | `#!python True` | Use `#!python sendStreaming` when the server's card opts in. Falls back to polling otherwise |
| `headers` | `#!python Optional[Mapping[str, str]]` | `#!python None` | Extra HTTP headers (auth, tracing) |
| `timeout` | `#!python Optional[float]` | `#!python 60.0` | Per-request timeout in seconds |
| `max_reconnects` | `#!python int` | `#!python 3` | Streaming reconnect attempts (see [Advanced](/docs/user-guide/a2a/advanced#streaming-reconnect)) |
| `reconnect_backoff` | `#!python float` | `#!python 0.5` | Backoff between reconnect attempts (seconds) |
| `polling_interval` | `#!python float` | `#!python 0.5` | Poll interval when streaming is off |
| `input_required_timeout` | `#!python Optional[float]` | `#!python None` | Cap how long the client waits on a HITL hook |
| `httpx_client_factory` | `#!python Optional[Callable[[], AsyncClient]]` | `#!python None` | Custom `#!python httpx.AsyncClient` (proxies, custom TLS, etc.) |
| `interceptors` | `#!python Sequence[ClientCallInterceptor]` | `#!python ()` | A2A SDK call interceptors |
| `grpc_channel_factory` | `#!python Optional[Callable[[str], Channel]]` | `#!python None` | Custom gRPC channel builder. The default follows the card URL scheme: `#!python grpcs://` / `#!python grpc+tls://` use system CA roots; other gRPC URL forms stay insecure. See [gRPC TLS](/docs/user-guide/a2a/client#grpc-tls) |
| `preset_card` | `#!python Optional[AgentCard]` | `#!python None` | Skip the discovery round-trip when the card is already known |
| `card_signature_verifier` | `#!python Optional[Callable[[AgentCard], None]]` | `#!python None` | Verify the JWS signature on every card consumed — fetched, preset and extended (see [Card Signing](/docs/user-guide/a2a/card_signing)) |
| `tenant` | `#!python Optional[str]` | `#!python None` | Multi-tenancy scope on a shared backend |
| `history_length` | `#!python Optional[int]` | `#!python None` | Server-side hint to truncate echoed `#!python Task.history` |
| `extensions` | `#!python Sequence[str]` | `#!python ()` | A2A extension URIs to activate on the connection (see [Extensions](/docs/user-guide/a2a/client#extensions)) |

### Constructing From a Pre-fetched Card

When the card has already been resolved (discovery service, on-disk cache), `#!python A2AConfig.from_card(...)` skips the network round-trip on connect:

```python linenums="1"
from ag2.a2a import A2AConfig

config = A2AConfig.from_card(card, prefer="jsonrpc", timeout=30.0)
```

`#!python card_url` defaults to the first interface URL on the card; pass `#!python card_url=...` to override.
