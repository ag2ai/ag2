---
title: Type checking
---

AG2 ships a `py.typed` marker, so every downstream project that runs a type checker treats this
library as typed. Keeping that promise is a ratchet: the set of checked files only ever grows,
and it lives in exactly one place.

## What is checked

The `files` list under `[tool.mypy]` in `pyproject.toml` is the whole answer. If the module you
are about to edit is in that list, a type error you introduce fails your pull request. If it is
not, nothing checks it.

Anything absent from the list is absent because it has not been cleaned up yet — not because it
is exempt. Two things are genuinely out of scope and say so at the end of the list: the demo
scripts at the repository root, and the documentation code samples.

Run the checker exactly the way CI does:

```bash
mypy
```

No arguments. The bare invocation reads `files` from `pyproject.toml`, so a clean local run, the
pre-commit hook and the pull-request job all check the same set.

## Checking a package that is not covered yet

You do not have to wait for a package's turn. Pass it on the command line and it is checked
instead of the allowlist, under the same strict settings:

```bash
mypy ag2/knowledge
```

Expect errors — that is the debt. When a package reports none, add it to `files` in the same
pull request that cleans it, so it is defended from then on.

## The two tiers of guarantee

"Checked" means two different things depending on the module, and the difference is worth
knowing before you rely on it.

- **Every pull request** (`.github/workflows/pr-checks.yml`) installs the `types` dependency
  group, which pulls a handful of extras, and runs `mypy` on Linux, macOS and Windows.
- **Nightly** (`.github/workflows/type-check.yml`) runs the same `mypy` across five Python
  versions and twenty-seven extras.

A module that imports a package behind an extra the pull-request job does not install is checked
against `Any` there: its imports are unresolved, so mistakes inside it survive until the nightly
run. Prefer adding the extra to the `types` group so the pull-request job really checks it. Where
an extra is too heavy to install on every pull request, the module's entry in `files` says it is
nightly-only, so nobody mistakes the weaker guarantee for the stronger one.

## The condition DSL

An event field is declared with the type of its value, so without help a checker reads
`ToolCallEvent.name == "search"` as a `bool`. The `ag2.mypy` plugin — registered in this
repository's `plugins`, and shipped for downstream projects to register in theirs — resolves
class-level field access to the field descriptor, whose comparison operators return a
`Condition`. `test/typing/` checks a fixture of every form the user guide teaches.

## Suppressions

A `# type: ignore[...]` carries its error code and a reason a later reader can act on. A
suppression with neither is indistinguishable from an abandoned one.

## The pre-commit hook

`mypy` runs as a local pre-commit hook via `scripts/pre-commit-mypy-run.sh`, which reinstalls the
`types` group before checking. It runs once per commit, over the same allowlist, so its cost
grows with coverage. If it becomes slow enough that people start skipping it, that is a signal
to reach for mypy's incremental cache in the hook rather than to shrink what is checked.
