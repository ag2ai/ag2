title: Type checking
---

AG2 ships a `py.typed` marker, so every downstream project that runs a type checker treats this
library as typed. That marker is a guarantee, not a claim: every importable module under `ag2/` is checked
under strict settings — on every pull request, bar the few modules [only checked
overnight](#the-two-tiers-of-guarantee) — so a public signature says what the code does, and
a name you import from AG2 does not hand your checker an `Any` it did not ask for.

## What is checked

Everything. `files` under `[tool.mypy]` in `pyproject.toml` is `["ag2", "test"]` — the library
under strict settings, the tests under the relaxed profile described [below](#the-test-tree).
Imports are followed for real, so an error at the seam between two packages is reported where it
happens.

Two paths are kept out of discovery by `exclude`, each with its reason beside it: the typing
fixtures, which fail the checker on purpose and are run one at a time by their own harness, and
`ag2/textual.py`, which cannot be imported at all until its keep-or-remove decision is made. The
demo scripts at the repository root and the documentation code samples are outside both trees:
they are examples and prose, not shipped code.

Run the checker exactly the way CI does:

```bash
mypy
```

No arguments. The bare invocation reads `files` from `pyproject.toml`, so a local run, the
pre-commit hook, the pull-request job and the nightly matrix all check the same two trees.

## The two tiers of guarantee

"Checked" means two different things depending on the module, and the difference is worth
knowing before you rely on it.

- **Every pull request** (`.github/workflows/pr-checks.yml`) installs the `types` dependency
  group, which pulls a handful of extras, and runs `mypy` on Linux, macOS and Windows.
- **Nightly** (`.github/workflows/type-check.yml`) runs the same `mypy` across five Python
  versions and twenty-seven extras.

A module that imports a package behind an extra the pull-request job does not install is checked
against `Any` there: its imports are unresolved, so mistakes inside it survive until the nightly
run. Prefer adding the extra to the `types` group so the pull-request job really checks it. Where
that cannot work — `tinyfish` needs Python 3.11 and the job runs 3.10 — the comment above `files`
names the module as nightly-only, so nobody mistakes the weaker guarantee for the stronger one.

## Containing an untyped dependency

An unstubbed dependency hands mypy `Any`, and that `Any` spreads out through the signatures of
*our* functions — which is precisely what AG2's `py.typed` marker promises a downstream project
will not get. Suppressing at each leak site says "we gave up here" once per site and nobody ever
revisits it. Contain it instead, in this order:

1. **Published stubs.** If the package ships a typed release or there is a `types-…` distribution,
   add it to the `types` dependency group. Nothing else to do.
2. **Follow it.** Many packages are fully annotated but ship no `py.typed` marker. Tell mypy to
   read them anyway and you get their real types, which keep working when the dependency changes:

   ```toml
   [[tool.mypy.overrides]]
   module = "some_package.*"
   follow_untyped_imports = true
   ```

   `mcp_ui_server` is the worked example — that one override is the whole of what `ag2/mcp_ui/`
   needed to be checked. `xai_sdk` is the largest: it ships `.pyi` for its generated
   protos and annotates the rest, and the override removed 21 of `ag2/config/xai/`'s 24 errors.
   Check for annotations before writing a boundary, even for an SDK that looks untyped.
3. **A local boundary.** Only when the dependency genuinely has no types to read: declare what we
   expect of it in the single module that touches it, so every caller past that point sees our
   types and one file changes when the dependency does.
4. **A suppression**, with its error code and a reason, when none of the above can work.

A dependency's own types can be wrong, too. `dashscope` bundles a stub that declares its async
call's stream arm as a synchronous `Generator`, and names a response class its runtime package
does not export — so an `isinstance` on it cannot run. The client casts at the call, once, and
says which half of the stub is wrong; that is a boundary, not a suppression.

Whichever you pick, confirm the dependency's extra is installed by the pull-request job — via the
`types` group or a group it includes — or the module is only really checked overnight.

## The optional-dependency fallback

Every public `__init__.py` behind an extra rebinds a name when its import fails, so a user gets
an install hint instead of a bare `ImportError`:

```python
try:
    from .redis import RedisStream
except ImportError as e:
    RedisStream = missing_optional_dependency("RedisStream", "redis", e)
```

mypy has already bound `RedisStream` to a class by then and rejects the rebind outright —
`Cannot assign to a type`. Show it only the real import; the fallback is runtime behaviour, and
reads as such:

```python
if TYPE_CHECKING:
    from .redis import RedisStream
else:
    try:
        from .redis import RedisStream
    except ImportError as e:
        RedisStream = missing_optional_dependency("RedisStream", "redis", e)
```

The names keep their true types, and the one duplicated import line is the whole cost. Do this
rather than suppressing per name — there are over a hundred of these bindings across the tree.

## The condition DSL

An event field is declared with the type of its value, so without help a checker reads
`ToolCallEvent.name == "search"` as a `bool`. The `ag2.mypy` plugin — registered in this
repository's `plugins`, and shipped for downstream projects to register in theirs — resolves
class-level field access to the field descriptor, whose comparison operators return a
`Condition`. `test/typing/` checks a fixture of every form the user guide teaches.

Bound to a name, `A | B` of two event classes is a type alias to the checker, not a value, and
no plugin hook reaches that decision. Annotate the name — `either: Condition = A | B` — and it
stays a condition.

## The test tree

Tests are checked too, under a relaxed profile — the `test.*` override in `pyproject.toml`. It
turns off only the settings that demand declarations (untyped and incomplete definitions,
untyped decorators and calls, `Any` from unimported dependencies): a test that takes nothing and
returns nothing gains nothing from saying so. Everything substantive stays on, `check_untyped_defs`
above all, so an unannotated test body is still checked.

That is what the profile is for: when a test double no longer satisfies the type it stands in
for, the checker says so, instead of the test quietly exercising something else. When a test
reports an error, fix the double before reaching for a suppression.

A guarantee about the public types themselves — an overload's return type, a form the checker
must refuse — goes in `test/typing/fixtures/` as a fixture with its expectations inline
(`# N: <note>`, `# E: <error>`). `test/typing/test_fixtures.py` runs mypy over each fixture and
compares.

## Suppressions

A `# type: ignore[...]` carries its error code and a reason a later reader can act on, on its
own line or the one above. A suppression with neither is indistinguishable from an abandoned one.

`warn_unused_ignores` is on, so a suppression that stops suppressing anything is itself an error.
When a fix makes one stale, delete it in the same change.

## The pre-commit hook

`mypy` runs as a local pre-commit hook via `scripts/pre-commit-mypy-run.sh`, which reinstalls the
`types` group before checking. It runs once per commit, over the same two trees, so its cost
grows with the codebase. If it becomes slow enough that people start skipping it, that is a signal
to reach for mypy's incremental cache in the hook rather than to shrink what is checked.
